# Документация по системе логирования в OrrClockLinux

## Обзор

В приложении реализована централизованная система логирования, которая позволяет гибко управлять отладочным выводом. Система построена на базе модуля `utils.logger` и предоставляет различные уровни логирования.

### Ключевые особенности:

- **Централизованное управление** - все логи управляются через единый интерфейс
- **Гибкая настройка** - отладочный режим можно включать/выключать через интерфейс настроек
- **Надёжное хранение** - состояние отладочного режима сохраняется в базе данных
- **Мгновенное применение** - изменения вступают в силу немедленно
- **Полная изоляция** - отладочные сообщения полностью скрыты в продакшн-режиме
- **Обратная совместимость** - поддерживается старый код с `print("[DEBUG] ...")`

## Основные компоненты

### Класс Logger

```python
class Logger:
    """
    Централизованный логгер для управления отладочным выводом.
    
    Пример использования:
        from utils.logger import logger
        
        # Отладочное сообщение (отображается только при включенном отладочном режиме)
        logger.debug("Это отладочное сообщение")
        
        # Информационное сообщение (отображается всегда)
        logger.info("Информационное сообщение")
        
        # Предупреждение (отображается всегда)
        logger.warning("Предупреждение")
        
        # Ошибка (отображается всегда, выводится в stderr)
        logger.error("Сообщение об ошибке")
    """
```

## Уровни логирования

1. **DEBUG** - отладочная информация (только для разработки)
2. **INFO** - общая информация о работе приложения
3. **WARNING** - предупреждения о потенциальных проблемах
4. **ERROR** - критические ошибки, требующие внимания

## Как включить/отключить отладочный вывод

### 1. Через интерфейс настроек (рекомендуемый способ)

1. Откройте настройки приложения
2. Перейдите в раздел "Отладочный режим"
3. Переключите переключатель в нужное положение
4. Нажмите "Применить" или "ОК" для сохранения настроек

### 2. Программно

```python
from utils.logger import logger

# Включить отладочный вывод
logger.set_debug(True)  # Автоматически сохраняет состояние в БД

# Отключить отладочный вывод
logger.set_debug(False)  # Автоматически сохраняет состояние в БД

# Проверить текущее состояние
if logger.debug_enabled():
    print("Отладочный вывод включен")

# Временно включить отладочный вывод для блока кода
with logger.debug_mode():
    # В этом блоке отладочный вывод будет включен
    logger.debug("Это сообщение будет выведено")
    
# Здесь отладочный вывод вернется к предыдущему состоянию
```

### 3. Напрямую в базе данных (только для администраторов)

```sql
-- Включить отладочный режим
UPDATE settings SET value = '1' WHERE key = 'debug_mode';

-- Выключить отладочный режим
UPDATE settings SET value = '0' WHERE key = 'debug_mode';
```

> **Примечание:** Изменение значения напрямую в БД вступит в силу после перезапуска приложения.

## Рекомендации по использованию

1. **Для отладочных сообщений** используйте `logger.debug()`:
   ```python
   logger.debug(f"Отладочная информация: {переменная}")
   ```

2. **Для информационных сообщений** используйте `logger.info()`:
   ```python
   logger.info("Приложение успешно запущено")
   ```

3. **Для предупреждений** используйте `logger.warning()`:
   ```python
   logger.warning("Обнаружена незначительная проблема")
   ```

4. **Для ошибок** используйте `logger.error()`:
   ```python
   try:
       # Код, который может вызвать исключение
   except Exception as e:
       logger.error(f"Произошла ошибка: {e}")
   ```

## Примечания

1. **Приоритеты настройки отладочного режима**:
   - Значение из базы данных (настраивается через интерфейс)
   - Значение по умолчанию (отключено)

   > **Важно:** Переменные окружения и аргументы командной строки больше не поддерживаются.

2. **Производительность**:
   - При отключенном отладке вызовы `logger.debug()` практически не влияют на производительность
   - Используется паттерн Null Object для минимизации накладных расходов
   - Проверка включен ли отладочный режим происходит за константное время O(1)

3. **Обработка ошибок**:
   - Все ошибки логирования перехватываются и выводятся в stderr
   - Сбои в логировании не влияют на работу основного приложения
   - При ошибке сохранения состояния в БД пользователь получает уведомление

4. **Миграция со старого кода**:

   - **Автоматическая фильтрация** - Сообщения с префиксом `[DEBUG]` автоматически фильтруются в зависимости от настроек отладочного режима
   - **Плавный переход** - Старый код продолжает работать, но рекомендуется перейти на новый API
   - **Рекомендуемый стиль**:
     ```python
     # Старый стиль (работает, но не рекомендуется)
     print("[DEBUG] Это отладочное сообщение")
     
     # Новый стиль (рекомендуется)
     logger.debug("Это отладочное сообщение")
     ```
   - **Преимущества нового стиля**:
     - Более высокая производительность
     - Лучшая читаемость кода
     - Больше возможностей (уровни логирования, форматирование)
     - Надёжная фильтрация сообщений

```python
# Старый стиль
print("[DEBUG] Это отладочное сообщение")

# Новый стиль
logger.debug("Это отладочное сообщение")
```
> Оба варианта будут вести себя одинаково с точки зрения отображения/скрытия отладочных сообщений в зависимости от настроек.

5. **Многопоточность**:
   - Логгер потокобезопасен и может использоваться из нескольких потоков
   - Сообщения из разных потоков не будут перемешиваться
   - Изменение состояния отладочного режима мгновенно применяется во всех потоках

6. **Интеграция с настройками**:
   - Состояние отладочного режима сохраняется в базе данных
   - Изменения применяются немедленно без перезапуска приложения
   - Интерфейс настроек всегда отображает текущее состояние

7. **Безопасность**:
   - Отладочные сообщения полностью отключаются в продакшн-режиме
   - Невозможно случайно оставить включенным отладочный вывод
   - Чувствительная информация не попадает в логи при отключенном отладочном режиме

## Примеры использования

### Базовое использование

```python
from utils.logger import logger

# Разные уровни логирования
logger.debug("Отладочная информация")  # Только при включенном отладочном режиме
logger.info("Информационное сообщение")  # Всегда видно
logger.warning("Предупреждение")  # Всегда видно, выделяется жёлтым
logger.error("Ошибка")  # Всегда видно, выделяется красным

# Проверка состояния отладочного режима
if logger.debug_enabled():
    # Дорогостоящие операции выполняются только при включенном отладке
    debug_data = collect_debug_data()
    logger.debug(f"Собранные отладочные данные: {debug_data}")
```

### Интеграция с настройками

```python
def on_debug_mode_changed(switch, value):
    """Обработчик изменения состояния переключателя отладки"""
    try:
        from utils.logger import logger
        logger.set_debug(value)
        print(f"[ИНФО] Отладочный режим {'включён' if value else 'выключен'}")
    except Exception as e:
        print(f"[ОШИБКА] Не удалось изменить отладочный режим: {e}")

# В интерфейсе настроек
debug_switch = Switch(active=logger.debug_enabled())
debug_switch.bind(active=on_debug_mode_changed)
```

### Временное включение отладки

```python
# Временно включить отладку для определенного участка кода
with logger.debug_mode():
    # В этом блоке отладочный вывод будет включен
    logger.debug("Это сообщение будет выведено")
    
# Здесь отладочный вывод вернется к предыдущему состоянию

# Временное отключение отладки (даже если она включена в настройках)
with logger.suppress_debug():
    # В этом блоке отладочный вывод будет отключен
    logger.debug("Это сообщение НЕ будет выведено")
```

### Условное логирование

```python
# Логировать только если включен отладочный режим
if logger.debug_enabled():
    # Дорогостоящая операция выполняется только при включенном отладке
    debug_info = collect_debug_info()
    logger.debug(f"Отладочная информация: {debug_info}")
```

### Временное включение отладки

```python
# Временно включить отладку для определенного участка кода
with logger.debug_mode():
    # Здесь отладочный вывод включен
    logger.debug("Отладочное сообщение внутри блока")
    
# Здесь отладочный вывод вернется к предыдущему состоянию
```

## Советы по отладке

1. **Поиск проблем с производительностью**:
   ```python
   import time
   from utils.logger import logger
   
   start_time = time.time()
   # Код, который нужно измерить
   logger.debug(f"Время выполнения: {time.time() - start_time:.4f} сек")
   ```

2. **Трассировка вызовов**:
   ```python
   import inspect
   from utils.logger import logger
   
   def some_function():
       logger.debug(f"Вызвана функция {inspect.currentframe().f_code.co_name}")
   ```

3. **Логирование исключений**:
   ```python
   try:
       # Код, который может вызвать исключение
   except Exception as e:
       logger.error(f"Ошибка в функции {inspect.currentframe().f_code.co_name}: {str(e)}")
       logger.debug("Подробная отладочная информация:", exc_info=True)
   ```
