## 1. Общая архитектура

Система настроек в приложении OrrClockLinux реализована с использованием модульной архитектуры и состоит из следующих компонентов:

- **SettingsWindow** - главный класс модального окна настроек (наследник `ModalView` из Kivy)
- **ColorSettings** - класс для управления настройками цветов
- **SettingsDatabase** - класс для работы с базой данных SQLite
- **Модульная структура** - настройки разделены на логические блоки в папке `settings_blocks`:
  - `colors.py` - настройки цветов
  - `notifications.py` - настройки уведомлений
  - `admin.py` - административные настройки
  - `header.py` - заголовок окна настроек
  - `footer.py` - нижняя панель с кнопками

## 2. Хранение данных

### 2.1. База данных
- Используется SQLite база данных `data/settings.db`
- Две основные таблицы:
  - `settings` - хранит настройки в формате ключ-значение
  - `window_settings` - хранит параметры окна (размер, положение)

### 2.2. Инициализация БД
При первом запуске создаются необходимые таблицы и устанавливаются значения по умолчанию:
- Цвет по умолчанию: 'lime'
- Размер окна по умолчанию: 715x1000 пикселей

### 2.3. Методы работы с настройками
- `get_setting(key)` - получение значения настройки по ключу
- `save_setting(key, value)` - сохранение настройки
- `save_window_settings(width, height, x, y)` - сохранение параметров окна
- `get_window_settings()` - получение параметров окна
- `apply_window_settings(window)` - применение сохраненных параметров к окну

## 3. Пользовательский интерфейс

### 3.1. Окно настроек
- Реализовано как модальное окно (наследник `ModalView` из Kivy)
- Состоит из трех основных секций:
  - Заголовок с названием настроек
  - Прокручиваемая область с настройками
  - Нижняя панель с кнопками управления
- Адаптивный интерфейс с поддержкой прокрутки
- Поддерживает различные размеры экранов (мобильные устройства и десктопы)

### 3.2. Доступные цвета

В приложении доступны 6 цветов для настройки отображения часов:

```python
colors = {
    'lime': (0, 1, 0, 1),    # Лаймовый
    'aqua': (0, 1, 1, 1),    # Бирюзовый
    'blue': (0, 0, 1, 1),    # Синий
    'red': (1, 0, 0, 1),     # Красный
    'yellow': (1, 1, 0, 1),  # Желтый
    'white': (1, 1, 1, 1)    # Белый
}
```

Выбранный цвет отмечается белой рамкой.

### 3.3. Секция уведомлений

Содержит настройки, связанные с уведомлениями о молитвах. Включает:
- Включение/отключение уведомлений
- Настройку времени напоминания
- Выбор звука уведомления

### 3.4. Админ-панель

Раздел с административными функциями:
- Включение/отключение отладочного режима
- Просмотр логов приложения
- Сброс настроек к значениям по умолчанию

## 4. Работа с цветами

### 4.1. Класс ColorSettings

Центральный класс для управления настройками цветов. Основные методы:
- `__init__(settings_window)` - инициализация с ссылкой на главное окно настроек
- `_on_color_button_press(button)` - обработка нажатия на кнопку цвета
- `save_color_settings()` - сохранение выбранного цвета в базу данных
- `_add_border_to_button(button)` - добавление рамки к выбранной кнопке

### 4.2. Представление цветов
- **Внутреннее представление**: кортеж (r, g, b, a), где каждый компонент от 0.0 до 1.0
- **В базе данных**: строковое имя цвета (например, 'lime', 'blue')
- **В интерфейсе**: кнопки с цветным фоном

### 4.3. Конвертация
- `get_color_tuple(color_name)` - преобразует имя цвета в кортеж RGBA
- `get_color_name(color_tuple)` - находит имя цвета по кортежу
- `create_color_section(settings_window)` - создает секцию выбора цвета в интерфейсе

## 5. Жизненный цикл настроек

1. **Инициализация**:
   - При запуске приложения создается экземпляр `MainWindowApp`
   - Инициализируется база данных настроек `SettingsDatabase`
   - Загружаются сохраненные настройки из БД
   - Применяются к интерфейсу

2. **Открытие настроек**:
   - Пользователь нажимает кнопку настроек в основном интерфейсе
   - Создается и отображается экземпляр `SettingsWindow`
   - Загружаются текущие настройки из базы данных
   - Отображается интерфейс с текущими значениями настроек

3. **Изменение настроек**:
   - Пользователь изменяет настройки через элементы управления
   - Изменения применяются к интерфейсу в реальном времени (предпросмотр)
   - При нажатии "Сохранить" настройки сохраняются в базу данных
   - Вызывается колбэк `apply_callback` для применения настроек к основному окну

4. **Отмена изменений**:
   - При нажатии "Отмена" или закрытии окна без сохранения
   - Изменения отменяются
   - Восстанавливаются предыдущие настройки из базы данных

5. **Закрытие приложения**:
   - При закрытии приложения сохраняются настройки окна (размер, положение)
   - Закрывается соединение с базой данных

## 6. Особенности реализации

1. **Модульная архитектура**:
   - Настройки разделены на логические модули в папке `settings_blocks`
   - Каждый модуль отвечает за свою секцию настроек
   - Легко добавлять новые секции настроек

2. **Обработка ошибок**:
   - Все операции с базой данных обернуты в try-except
   - При ошибках загрузки настроек используются значения по умолчанию
   - Ведутся логи всех операций для отладки

3. **Производительность**:
   - Минимальное количество обращений к БД
   - Кэширование часто используемых значений
   - Асинхронная загрузка тяжелых компонентов

4. **Адаптивность**:
   - Интерфейс адаптируется под размер экрана
   - Поддержка как мобильных устройств, так и десктопов
   - Учитывается плотность пикселей (dp)

5. **Безопасность**:
   - Валидация вводимых данных
   - Защита от SQL-инъекций при работе с базой данных
   - Безопасное хранение чувствительных данных
